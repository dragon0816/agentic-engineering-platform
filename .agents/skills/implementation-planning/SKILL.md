# Implementation Planning

1. Read architecture, active phase spec and HANDOFF.
2. State the requirement and acceptance criteria.
3. Identify affected contracts and architecture boundaries.
4. Identify files/modules to add or change.
5. Define tests before implementation details.
6. Split work into small independently verifiable slices.
7. Identify side effects, migration risks and approvals.
8. Prefer the smallest reversible implementation.
9. Do not broaden scope merely because adjacent refactoring is attractive.
10. Record meaningful plan/state changes in HANDOFF when work spans agent sessions.
