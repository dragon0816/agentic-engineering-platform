  最多一半的結果來自這些說明行；導覽頁不當證據。

正式 vault 從頭到尾都沒有改動。

## 可能原因（尚未逐題驗證）

1. **說明行搶走搜尋名額。** 每輪最多一半的結果來自 index 說明行。說明行很短，
   BM25 對它的分數偏高，可能把原本靠內文命中、更準確的頁面擠掉。
   例如 Q1071 從 0.44 掉到 0，Q0846 和 Q0196 也各掉了 0.25。
2. **「不足」變多（4 → 7）。** 證據頁變多但內容較淺，Harness 驗證更容易判為
   證據不足或沒有依據。
3. **兩個因素混在一起。** 這次同時改了資料（index 和 frontmatter）與程式（K2.4），
   無法分辨是哪一個造成退步。
4. **單次量測。** 同一設定沒有重跑過，run 之間的波動幅度未知。涵蓋率只差 0.046，
   但 PASS 少了 5 題，退步方向一致。

## 建議的下一步（等擁有者決定）

- A：只用候選資料、不套 K2.4 程式，再跑一次，把資料和程式的影響分開。
- B：保留 K2.4，但把說明行的命中改成「附加」在內文結果之後，不再佔前一半，再跑一次。
- C：暫停 K2 對查詢的影響，分層 index 只給 ingest 使用（這也是它最初的目的：
  2007 頁的 relevance prompt 太大），直接進 K3。

## 追加：方案 A（core-008，2026-10-11）

候選資料不變，程式改為 revert 後的版本（ce75671，沒有 K2.4）。

| | core-005 | core-007（資料＋K2.4） | core-008（只有資料） |
|---|---|---|---|
| 可回答 22 題涵蓋率 | 0.395 | 0.349 | 0.386 |
| 可回答 22 題 PASS | 16 | 11 | 13 |

解讀：

- 只換資料也一樣變差，所以退步不全是 K2.4 程式造成的。K2.4 讓涵蓋率再多掉了約 0.04。
- 舊程式不讀 frontmatter，所以 core-008 裡雙語摘要完全沒有作用。真正改變的是 `index.md`：
  原本 2,910 行的扁平目錄，查詢會先用它找頁面；現在只剩 17 行分類，這條路等於斷了。
  另外有 7 題的答案直接引用了 `wiki/index/` 的子目錄頁當證據。舊程式只排除 `index.md`，
  沒有排除子目錄頁。
- 因此，雙語 index 對查詢有沒有幫助，到目前為止都還沒有被乾淨地測到。兩次測試都同時
  拿掉了原本扁平目錄提供的導覽。
