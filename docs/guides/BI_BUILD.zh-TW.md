# BI 知識庫：從檔案到大家看得到的卡片

給第一次用的同事。照頁面上的步驟走，每一節寫要按什麼、會看到什麼。附截圖的逐步操作在
[`BI_SOP.zh-TW.md`](BI_SOP.zh-TW.md)；寫判讀規則（Skill）的範例在
[`BI_SKILL_EXAMPLES.zh-TW.md`](BI_SKILL_EXAMPLES.zh-TW.md)。

位置：Agent Web → **Knowledge** → 分頁 **BI 卡片**。頁面上方三個分頁：**建立與匯入**、**Dashboard**、**卡片**。

## 先知道這幾件事

- **AI 的結果是有出處的候選，不是完整答案。** 每個值都標了它從原文哪一段來，你審核過才寫入。AI 會漏，
  也會讀錯；沒有出處的值不要照單全收。
- **同樣的輸入，每次跑的結果可能不同。** 要比較時看「進階：擷取設定與試跑」的「比較兩次試跑」。
- **每個領域有自己的負責人。** 同一個知識庫可以有好幾個領域（例如 AIDC、海事），各自的人在自己的領域
  加檔、改規則、審核。AEP 不管權限，這是大家的約定：不要改別人領域的東西。
- **大家要裝同一個版本的 AEP。** 知識庫放在共用資料夾，每台電腦依它重建卡片；版本不同時，可能讀不懂
  別人新寫的內容（例如提示「知識庫的 schema 檔……和這台電腦上的同一版本內容不同……請更新 AEP」）。

## 什麼時候別人看得到

| 你做到哪 | 誰看得到 |
|---|---|
| 轉檔、審核、確認匯入、改規則 | 只有你這台電腦（來源表上寫「commit、push 後才會放上去」） |
| Commit | 還是只有你；這次的改動有了名字，可以整批回復 |
| Push 給大家 | 同事的電腦在 OneDrive 同步後看得到卡片 |
| 加 tag，再「發佈 tag」 | 大家的 Agent（對話裡問問題）讀這個發佈的版本 |

步驟 3「版本」區塊的第一行會寫 Agent 現在讀哪一版，例如「Agent 讀的是發佈版本「2026q4」；之後 push 的
內容要再發佈，Agent 才會讀到。」

## 0. 知識庫與工作領域（頁面最上面一列）

1. **知識庫**下拉選單選一個知識庫。第一次用：按 **新增知識庫**，填「知識庫名稱」、「目的（Agent 依這段話
   判斷什麼問題該查它）」、選 Schema、「放在哪個資料夾底下（SharePoint／OneDrive 同步的資料夾）」、你的
   作者名稱，按 **建立**。同事已經建好的，按 **加入**，指到那個 vault 資料夾（裡面有 `vault.json`）。
2. **工作領域**下拉選單選你負責的領域。之後三個步驟、Dashboard 和卡片都只看這個領域；「全部領域」只能看，
   不能加檔或 Ingest（會提示「先在上面選工作領域，才能加入檔案或 Ingest。」）。
3. 沒有你的領域：按 **新增領域**，填領域名稱（中文名稱時另外填英文資料夾名稱），按 **建立**。新領域要
   commit、push 後同事才看得到。

下面一行是這個知識庫的狀態：幾張卡片、別人 push 了還沒套用的、你還沒 push 的、還沒 commit 的改動。

## 1. 步驟 1／3・輸入與轉檔

1. 選 **機密等級**（不確定就用預設的 `INTERNAL`）。
2. 按 **選檔**，選一個或多個檔案（Markdown、純文字、Word、PDF、PowerPoint、Excel、CSV／TSV）。旁邊會顯示檔名。
3. 按 **轉檔**。來源表多一列，「Markdown」欄是「第 1 版」。轉不了的檔案會寫原因。
4. 按那一列的 **看／改**：右邊打開轉檔結果。**顯示**選「預覽」看排版，選「編輯」可以修正，寫「這一版的說明」
   後按 **存成新版次**（原始檔不會改）。之後的 Ingest 讀最新一版。
5. 按 **下一步：Schema 與 Ingest**。

## 2. 步驟 2／3・Schema 與 Ingest

### a 類別與規則：schema、Skill、資料處理程式

- **判讀規則（skills）**：告訴 AI 這個領域要做哪些卡、什麼算證據。沒有規則時，頁面會說 AI 只會找預設的
  幾種卡。按 **和 AI 新增規則**，或在規則那列的選單按 **和 AI 一起修改**：右邊打開 AI 面板，寫你要什麼，按
  **送出**。AI 會在草稿上試跑給你看，你按 **套用為新版次** 才會存。範例見
  [`BI_SKILL_EXAMPLES.zh-TW.md`](BI_SKILL_EXAMPLES.zh-TW.md)。
- **Schema**（卡片有哪些類型和欄位）：在 **進階：Schema** 按 **和 AI 調整 schema**。AI 的建議按 **套用到草稿**，
  再按 **發布為新版本**，最後在版本列表選這一版、按 **套用升級**。schema 改了全知識庫都受影響，請和其他
  領域的人先說好。
- **資料處理程式**（把報表整理成能讀的樣子的 Python）：AI 面板不會寫程式，它會把這類需求列在
  「需要工程開發」。程式由會寫的人在 **進階：規則與程式** 加，別人加的要你按 **看過了，核准** 才會執行。

### b Ingest

1. **使用的擷取 Skill** 選這個領域的規則（通常已選好）。
2. 按 **Ingest**。頁面顯示「AI 判讀中…（第 n／m 段）」，結束後自動進入審核。

想先看看結果再決定：**進階：擷取設定與試跑** 的 **試跑** 不會留下任何東西。

### c 審核

1. **待審核的執行**下拉選單選要審的那一次（同事從別處開始的也在這裡）。
2. 左邊是候選卡表格，可以用 **卡片類型**、**狀態**（全部／待決定／已接受／已拒絕）篩選。點一列，右邊顯示
   欄位、引用，下方是原文並標出引用的那段。
3. 按 **接受** 或 **拒絕**：那一列馬上出現藍色 ✓ 已接受 或紅色 ✕ 已拒絕，並跳到下一張還沒決定的。
   重新整理頁面後還在。
4. 欄位值是另一張卡的名字時是連結，點了在右邊打開那張卡；來源檔名點了打開那份原文；按
   **回到候選卡** 回來，表格位置不會跑掉。
5. 一次接受全部：**接受所有沒有錯誤的候選卡**（有錯誤或和既有卡片同名的要一張張看）。
6. 「新增出處」的列：內容和現有卡片一樣，接受後只是把這份來源加進出處，卡片內容不變。
7. **待審提案**（同一欄位有不同的值，例如兩個來源說法不同）也在這一步：左右兩欄是目前的值和提議的值。
   用短很多的文字取代長文時，要再按一次 **確定取代**。接受後，提議的出處成為這個欄位的出處，舊值和它的
   出處留在卡片的歷史裡。
8. 按 **下一步：確認寫入**，看一下數字，按 **確認匯入**。寫錯了在結果頁按 **復原這次匯入**。

## 3. 步驟 3／3・測試、commit、push、發佈

### Benchmark：問答題

展開 **Benchmark**。按 **新增題目**（題目、必須提到、不可以說），或 **和 AI 一起出題**，勾選後按
**加入測試題**。按 **跑測試**：結果比較「你現在的內容」和「大家目前讀的版本」。有題目退步時 push 會被擋下
（「Push 會被擋：…」）；還沒跑過測試也能 push，但會註明沒有測試。

### Dashboard

展開 **Dashboard**。按 **和 AI 做新分析**，說你要看什麼；看過預覽按 **存成分析**。分析只畫在 AEP 裡；要在
Atlas 看，見下面「Atlas」。

### 版本：commit、push、tag、發佈

1. 「這次改動的目的（commit 一定要寫…）」填一句話，按 **Commit**。上面的表格列出這次帶上的每一項
   （名稱、種類、領域、改動）；選了一個領域卻帶到別的領域時，會提示「這次 commit 也會帶上其他領域的改動」。
2. 按 **Push 給大家**。
3. 要讓 Agent 讀到：在 **歷史與發佈** 那一列的 **動作** 選 **加 tag**（例如 `2026q4`），再按 **發佈 2026q4**，確認。

### 有衝突時

兩個人同時改了同一個地方，push 時會停下並列出每一項：左邊「你的」，右邊「別人已 push 的」。每一項選
**用我的**、**用別人的**，或欄位可以 **自己填**，全部決定後再按 **Push 給大家**。同步時才發現的衝突會變成
卡片上的待審提議，到「待審提案」決定。

## Atlas

Atlas 是另外安裝的程式，不在 AEP 的安裝包裡。裝好並啟動後，Dashboard 分頁的 **在 Atlas 開啟個人 Dashboard**
會打開它。它不在預設位置 `127.0.0.1:8127` 時，在 **Atlas 位址** 填正確的網址。Atlas 沒有回應時頁面會寫
「Atlas 沒有回應…請先啟動 Atlas（python -m server --port 8127）…」。

## 這一版還沒有的

- **把知識庫上傳到 Shared Platform**：共用靠同步資料夾（OneDrive／SharePoint）和發佈 tag。
- **加密**：知識庫的內容照原樣放在同步資料夾，權限由那個資料夾的分享設定決定。
