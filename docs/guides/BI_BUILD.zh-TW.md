# BI 卡片「建立與匯入」使用指南

給負責 BI 知識領域、但不寫程式的維護者。讀完你應該能把一份會議紀錄、競品週報或 Excel 報表，
安全地變成 BI 卡片：知道每個按鈕做什麼、什麼時候才會真的寫入、怎麼判讀 AI 的結果，以及寫錯了怎麼復原。

設計規格在 [`docs/phases/BI_INGEST.md`](../phases/BI_INGEST.md)，API 契約在
[`docs/CONTRACTS.md`](../CONTRACTS.md) 的 "BI ingest runs" 等段落；這份指南只講操作。

## 0. 在哪裡

Agent Web → **Knowledge** → 分頁 **BI 卡片** → 先在上方的資料集選單選好資料集 → 檢視分頁
**建立與匯入**。

- 頁面上方會寫「寫入目的地：資料集「…」・schema …」。要換資料集，用上方的資料集選單，不是在這裡。
- 從 Shared Platform **訂閱**來的資料集是唯讀的：看不到「建立與匯入」，只能看 Dashboard 和卡片。
- 舊的「匯入 CSV」分頁已移除（2026-10-28）；CSV 一樣在「建立與匯入」加入，走表格規則。
- Dashboard 上的「**在 Atlas 開啟個人 Dashboard**」開啟你自己的 Atlas；Atlas 沒有在執行時會直接告訴你。
  Atlas 的網址在旁邊的「Atlas 位址」設定（只存在這個瀏覽器，預設 `http://127.0.0.1:8127`）。

六個步驟顯示在頂端的步驟列：**1 來源 → 2 Schema → 3 擷取 Skill 與試跑 → 4 逐卡審核 → 5 確認寫入 →
6 結果**。前面的步驟沒完成時，後面的步驟按不下去（提示「先完成前面的步驟」）。頁面會記得你停在
哪一步、選了哪份來源與哪次執行，重新整理後可以接著做。

## 1. 什麼時候會寫入什麼

最重要的一張表。只有一個按鈕會寫入卡片：步驟 5 的 **「確認匯入」**。

| 你做的事 | 寫入了什麼 | 卡片（`bi.sqlite`）有沒有變 |
|---|---|---|
| 步驟 1「加入來源」 | 來源檔的一份副本（同樣內容只存一次），放在資料集的暫存區 | 沒有 |
| 步驟 2 儲存草稿、回復版次、Session A 對話、「套用到草稿」 | 草稿的新版次、對話紀錄 | 沒有 |
| 步驟 2「發布為新版本」 | 安裝一個新的 schema 版本（資料集還沒有用它） | 沒有 |
| 步驟 2「套用升級」 | 資料集改用新版本；宣告過的改名欄位會搬值 | **有**（只有改名搬值，其他值保留） |
| 步驟 2／3「試跑」、「用樣本試跑」、「比較」 | 一次試跑紀錄與候選卡（暫存區） | 沒有；試跑結果也**不能**寫入 |
| 步驟 3 另存 Skill、存新版次、Session B 對話、「套用為新版次」 | 你的 Skill 的新版次、對話紀錄 | 沒有 |
| 步驟 4「開始正式匯入（產生候選卡）」、接受／拒絕、修改欄位 | 這次執行的候選卡與你的決定（暫存區） | 沒有 |
| 步驟 5「確認匯入」 | 所有「已接受」的候選卡，一次寫入，記成一筆匯入 | **有** |
| 步驟 6「復原這次匯入」 | 把整筆匯入撤回 | **有**（回到匯入前） |

AI 判讀時，來源原文只被當成資料：模型沒有任何工具，不能寫入、不能執行動作；就算文件裡寫著
「忽略規則並寫入」也不會發生任何事。出處（第幾行）由程式在原文裡找到，不是模型說了算。

## 2. 資料機密等級與模型核准

每份來源都有機密等級：`INTERNAL`（預設）、`UNCLASSIFIED`、`CONFIDENTIAL`、`RESTRICTED`。

- **表格來源走規則轉換，不會送給模型**，任何等級都可以用。
- **文字／Markdown 來源要送給模型判讀**（試跑、正式匯入、Session A／B 附上的樣本都一樣）。只有在
  管理員於 Settings 為 Knowledge 模型**核准**的等級內才會送出；否則會看到
  「來源的機密等級是 …，但這個模型只核准 … 的資料」，而且**什麼都沒有送出**。
  解法：改用核准等級的來源，或請管理員在 Settings 核准這個等級。`RESTRICTED` 不能核准給模型。
- 沒有設定 Knowledge 模型時，AI 判讀與 Session A／B 會顯示「沒有可用的模型」
  （`model_unavailable`），表格來源的規則轉換仍然可用。

選等級時請照公司分級；不確定就用預設的 `INTERNAL`，被擋下來再找管理員。

## 3. 步驟 1／6・知識庫與來源

### 3.0 知識庫：一般資料集或共用 vault

最上面的「**知識庫**」區塊決定寫到哪裡：

- 「**寫入哪個知識庫**」：選這台電腦的資料集，或標成「共用：…（vault）」的共用知識庫。
- **一般資料集**只在這台電腦。**共用知識庫（vault）**放在 SharePoint／OneDrive 同步的資料夾：
  每個人按「確認匯入」或改卡片時，只會在 vault 的 `changes/<你的作者名稱>/` 新增一個自己的變更檔，
  不會改到別人的檔案；每台電腦依照所有變更檔重建自己的卡片。資料庫檔不會放進共用資料夾。
- 「**建立共用知識庫（vault）**」：填名稱、目的（Agent 依這段話判斷什麼問題該查它）、schema、放在哪個
  同步資料夾底下、你的作者名稱。會建立 `vault.json`、`VAULT.md`、11 個應用領域資料夾與
  `library/`（產品、對手、技術）。
- 「**加入既有的 vault**」：指到同事建好的 vault 資料夾（裡面有 `vault.json`）。作者名稱已經有人用，
  會被擋下；如果是你本人換電腦，勾「接續」。
- 「**把這個資料集轉成 vault**」：把這台電腦的資料集整份放進新的 vault（原本的資料集不會被改動）。
- 選到 vault 時會先同步，並顯示：已套用幾個變更檔、還有幾個沒套用、卡片數、上次同步；
  「**衝突**」（兩個人從同一個舊值改了同一個欄位：後送的變成卡片上的待審提議）、
  「**合併提示**」（同一張卡被兩人各建一次，已合成一張）、還不能讀的變更檔（可能還在同步）。
  「**立即同步**」可以隨時再同步。讀不到共用資料夾時可以看卡片，但不能寫入。

**注意**：真實的 SharePoint 資料夾請在你自己確認過、有備份後再建立或加入；測試請用一個空的暫存資料夾。

### 3.1 來源

- **機密等級**：這次加入的檔案都用這個等級（見第 2 節）。
- **加入來源**：AEP 保留一份副本，不會移動或修改你的原始檔。同樣內容重複加入只存一次。

- 可以加入 CSV、TSV、Excel、PDF（有文字層的）、Word、PowerPoint、Markdown、文字。每份來源加入時都會
  **轉成 Markdown**：表格變成 Markdown 表格，PDF 每頁一段，Word／PowerPoint 照標題、段落、表格順序。
  掃描的 PDF 沒有文字層，會直接告訴你不支援。
- 來源表的「**Markdown**」欄顯示目前是第幾版；按「**看／改**」打開：可以看每一版，改目前這一版後按
  「**存成新版次**」（原始檔不會改）。之後的試跑與正式匯入都讀**最新的版次**，出處的行號也指向那一版。
  有人比你先存了新版次時，你的修改不會存，畫面會告訴你最新是第幾版，請重新載入再改。
- 「**格式**」欄寫預設用哪個擷取 Skill：表格用「表格規則」，文件與文字用「AI 擷取」。在步驟 3 把表格改選
  「AI 擷取」，就會把表格的 Markdown 交給 AI 判讀。
- 在「**使用**」欄點選這次要處理的來源，再按「**下一步：Schema**」。

## 4. 步驟 2／6・Schema

Schema 決定有哪些卡片類型、每種卡片有哪些欄位、哪些欄位必填、哪些欄位只能填固定的值。

### 4.1 目前版本與升級

- 第一行寫「這個資料集目前使用 …」。
- 如果同一個 schema 有其他版本，會列在「同一個 schema 的其他版本」，旁邊有「**預覽升級**」。
- 預覽只顯示影響、不寫入：
  - 「改名後移動的值」：新版本把欄位改名，舊值會搬到新欄位。
  - 「保留但隱藏（新版本沒有這個欄位）」：值不會被刪，只是不顯示、不搜尋；改回有這個欄位的版本會再出現。
  - 「值已不在允許值裡，保留待審」：原值保留，不會被偷偷改掉。
  - 「新的必填欄位，這些卡片缺少」：之後要補。
  - 「不能升級：…。請另建資料集。」：刪除卡片類型、改變命名方式或欄位型別這類**破壞性**變更不能升級。
- 「**套用升級**」才真的改資料集。若預覽之後有人改了卡片，會要求重新預覽。
- 升級前開始的執行不能再審核或寫入（「資料集的 schema 已從 … 改為 …；請用同樣的來源重新執行」），
  請重新產生候選卡；你存的擷取 Skill 會標成
  「schema 已更新，請重新試跑」，用新版本試跑一次到可審核後才能正式匯入。

### 4.2 草稿

- 「**從目前版本建立草稿**」：複製目前版本當第 1 版。
- 「**草稿內容（JSON）**」可直接編輯；「這一版的說明」寫一句話；「**儲存為新版次**」存成新的版次
  （舊版次永遠保留）。儲存草稿**不會**改動任何資料集。
- 「和基礎版本的差異」列出每個變更，⚠ 標記的是破壞性變更。有錯誤時會寫「有 … 個問題，不能發布」。
- 「版次」清單裡每一版都有「**回復到這一版**」：把那一版的內容存成新的版次（不會刪掉之後的版次）。
- 「**用樣本試跑**」：用草稿這一版、拿步驟 1 選的來源試跑（第 5 節的同一套流程），**不安裝 schema、
  不寫入**；結果只能看，不能寫入。
- 「**發布為新版本**」：安裝成一個新的版本號。發布後資料集**還沒有**用它，要回到 4.1 按「預覽升級」。

### 4.3 和 AI 一起調整 schema（Session A）

適合「我想追蹤某個領域，現有 schema 夠不夠用？」這類問題。對話區一進步驟 2 就看得到，不用先建草稿：
還沒有開啟草稿時，送出第一句話會先從目前版本建立一份草稿，建議都套用在這份草稿上。沒有可用的模型時，
送出不會建立任何東西。

1. 「**你的目標（用自己的話）**」，例如「追蹤機器人產業的技術、應用與客戶訊號」。
2. 「**附上的樣本來源**」最多 5 份，合計上限 12000 字；送出前會顯示會送出哪些資料。
3. 「**你想怎麼調整 schema**」寫需求，按「**送出**」。每次送出只呼叫一次模型。
4. AI 的回答會給一個結論：「**照用目前的 schema**」、「**擴充這份 schema**」或
   「**需要新的 schema（另建資料集）**」，加上「理由」、「假設」、「缺少的資訊」、套用後的差異與範例卡片。
5. 你同意才按「**套用到草稿**」（存成草稿的新版次）。不按就什麼都不會變。之後照 4.2 試跑、發布、
   再照 4.1 升級——這三件事一律由你分開按。

## 5. 步驟 3／6・擷取 Skill 與試跑

「擷取 Skill」是一份可重複使用的讀法：文字來源用「判讀規則」交給 AI，表格來源用「配方」做規則轉換。
「**使用的擷取 Skill**」選單一定有兩個內建的：

- 「**AI 擷取（內建）**」：讀文字與 Markdown，用下方的判讀規則（留空就是預設規則）。
- 「**表格規則（內建，不用模型）**」：照欄位名稱把表格轉成卡片；多表格報告才需要下方的配方。

選了表格來源時預設是「表格規則」，其他來源預設是「AI 擷取」。內建 Skill 本身不會被改動。

### 5.1 用內建 Skill 直接試跑

- 「**卡片類型（單一表格）**」：單一 CSV／TSV 時指定要轉成哪種卡片，或「自動判斷」。
- 「**配方 JSON**」：多表格的 Markdown／Excel 報告才需要（通常由工程或 AI 協助寫好）；單一表格留空。
- 「**判讀規則**」：文字或 Markdown 來源由 AI 判讀；留空使用預設規則（只寫來源支持的內容、預測標成推論、
  沒有明確客戶需求就不是商機……）。例如寫「沒有文件依據的需求標成推測；依應用而不是產品拆卡」。
- 「**試跑**」：產生候選卡給你看，顯示「試跑完成（沒有寫入）」和候選、新建、更新、略過、錯誤、警告的數量。
  AI 判讀時會顯示「AI 判讀中…（第 n／m 段）」。

AI 判讀預設只產生三種卡片：訊號（Signal）、技術（Technology）、應用（Application）。要讀其他類型
（例如商機 Opportunity、競爭對手 Competitor），請在 Session B 請 AI 調整「卡片類型」後套用。

### 5.2 另存自己的 Skill、版次與回復

- 「**另存為新的 Skill（名稱）**」＋「**用下方設定另存 Skill**」：把目前的設定存成你的 Skill 第 1 版。
- 「**使用的擷取 Skill**」選單選你的 Skill 後，試跑與正式匯入都用它。
- 「**把上面的設定存成這個 Skill 的新版次**」：每次修改、套用 AI 建議或回復都是新的版次，舊版次保留。
- 每個版次都有「**回復到這一版**」（存成新的版次）。

### 5.3 和 AI 一起調整擷取 Skill（Session B）

對話區一進步驟 3 就看得到。在「**你想怎麼調整這個 Skill**」寫，例如「沒有文件依據的需求標成推測」，
按「**送出**」。

- 選的是內建「AI 擷取」時，送出第一句話會先另存一份「AI 擷取（我的版本 …）」，之後的建議都套用在它上面。
- 內建「表格規則」是自動對應欄位，沒有可讓 AI 調整的設定；要調整，先在下方貼配方（送出時另存成你的
  Skill），或改選「AI 擷取」。
- 沒有可用的模型時，送出不會另存任何東西。

畫面會先說明用哪個模型、送出哪些資料（Skill、最近兩次試跑的候選卡、來源前段，上限 12000 字）。AI 只會
提出建議，你按「**套用為新版次**」才會改 Skill。建議裡「需要工程開發（Skill 做不到，沒有套用）」的項目
不會被套用，也不代表已經可以做到。

### 5.4 比較兩次試跑

選同一份來源的「較早的試跑」與「較新的試跑」，按「**比較**」：看到只在其中一次出現的候選卡、
每個欄位的值或依據的改變、多出或少了的警告，以及候選卡、推論欄位、警告、錯誤的數量。比較不會寫入。
典型用法：Skill 改版前後各試跑一次，確認改動有達到效果。

## 6. 步驟 4／6・逐卡審核

1. 按「**開始正式匯入（產生候選卡）**」。這才是要寫入用的執行（試跑的結果不能寫入）。仍然還沒寫入任何卡片。
2. 上方的標籤顯示執行編號與狀態、候選與各種數量。
3. 左邊是候選卡清單（名稱、類型、新建／更新／不變／略過、待決定／已接受／已拒絕、錯誤數、警告數）；
   點一張看右邊的明細。

### 6.1 讀明細

- 第一行：「**新卡片**」、「**對應到既有卡片（版本 n）**」或「**有名稱相近的既有卡片**」。
- **紅色**是錯誤：必須先修正才能接受。**黃色**是警告：提醒你檢查，不擋接受。
- 欄位表：欄位、新值、**依據**、**出處**、目前值（新增／變更／相同／保留人工值，改成提議）、修改。

### 6.2 依據：有出處／推論／無出處／人工

| 標籤 | 意思 | 你該做的事 |
|---|---|---|
| **有出處** | 原文寫了；出處欄顯示引用的句子與行號（如 `line_start 6・line_end 6`），行號由程式在原文裡找到 | 對照原文確認意思沒有被扭曲 |
| **推論** | AI 自己推的（預測、可能的需求）；警告會寫「… 是推論：理由」 | 判斷推論合不合理；不同意就改值或拒絕 |
| **無出處** | 沒有原文依據。若警告是「模型引用的原文不在來源中，改標為無出處」，代表 AI 引用了一句原文裡不存在的話 | 特別小心：自己查原文，必要時改值或清掉 |
| **人工** | 你在審核時改過的值 | — |

表格來源（規則轉換）的值都是「有出處」，出處是那一格；預設值沒有出處，顯示「無出處」。

### 6.3 常見的錯誤與警告

- **值不符合 schema**（例如只能填固定值的欄位填了別的字）：紅色錯誤，在「修改」欄改成允許的值，按「存」。
- **必填欄位缺少**、**擷取 Skill 的必要欄位檢查沒過**：補上欄位再接受。
- **商機沒有明確客戶與需求**：「來源沒有明確的客戶與需求，這只是可能的方向，不是商機；預設拒絕」。
  這張候選卡已經是「已拒絕」；除非你確認原文真的有客戶需求，否則維持拒絕。
- **不同段落寫了不同的值**（`value_conflict`）：保留第一段的值，請自己判斷哪個對。
- **模型提出的欄位／類型不在 schema**：已經丟掉，只是告訴你。
- 規則轉換才有的：**名稱經別名合併**（`alias_merged`）、**同名卻是另一種卡片**（`role_conflict`，預設略過，
  你可以改成新建）。

### 6.4 名稱相近

「有名稱相近的既有卡片」表示資料集裡已有一張只差空白、標點或大小寫的卡片（例如 `Wi-Fi 7` 與 `WiFi7`）。
這是錯誤，必須選一個：

- 「**新建**」：確定是不同的東西。
- 「**合併到既有卡片 …**」：是同一個東西，更新那張卡片。
- 「**略過**」：這次不處理。

注意：只差空白、標點、大小寫的名稱在**同一次執行**內會自動合併成一張候選卡；中英文名稱（例如
「聯發科」與「MediaTek」）程式無法判斷，請在審核時自己合併或拒絕其中一張。

### 6.5 決定

- 每張卡片按「**接受**」、「**拒絕**」或「**待決定**」。
- 改欄位：在「修改」欄輸入（清單欄位用「；」分隔），按「**存**」。改過的欄位依據變成「人工」，並留下修改紀錄。
- 「**接受所有沒有錯誤的候選卡**」：一次接受所有待決定、沒有錯誤、不是略過的候選卡。用之前請至少看過
  推論與無出處的欄位。
- 原本由人設定過的卡片欄位不會被覆蓋，會變成「待審提議」，之後在卡片頁接受或拒絕。

### 6.6 部分完成與重試

很長的文件會被切成幾段分別判讀。某些段落失敗時，執行狀態是 `partial`，畫面寫「有 n 段沒有判讀成功
（第 a–b 行：…）。其他候選卡可以先審核。」

- 已經成功的候選卡可以先審核、甚至先寫入。
- 「**重試失敗的段落**」只重跑失敗的段落，新找到的候選卡會合併進來，你已做的決定保留。
- 全部段落都失敗時狀態是 `failed`，不能寫入；修好模型設定後按重試。
- 模型回答格式不對時會自動重問最多 3 次，仍不行該段落才算失敗。

按「**下一步：確認寫入**」（至少接受一張才按得下去）。

## 7. 步驟 5／6・確認寫入

摘要列出目的地資料集與 schema、新建幾張、更新幾張、拒絕或略過幾張、還沒決定幾張（不會寫入）。

按「**確認匯入**」：所有已接受的候選卡**一次**寫入，記成一筆匯入。

- 如果審核之後有人改了相關卡片（或別人先建立了同名卡片），會出現「沒有寫入：有卡片在審核後被修改或
  新增……」並列出卡片名稱（`cards_changed`），**一張都沒有寫**。按「**重新檢查並回到審核**」：系統用最新的
  卡片重新比對，差異有變的候選卡回到「待決定」，你再看一次、接受，再確認匯入。
- 網路斷線後重按也安全：同一次執行只會寫入一次。

## 8. 步驟 6／6・結果

顯示執行編號、匯入編號，以及新建、更新、不變、成為待審提議、略過、未決定（沒有寫入）的數量。

- 「**到卡片查看**」、「**看 Dashboard**」。卡片明細會顯示每個欄位的來源、行號與依據。
- 「**復原這次匯入**」：新增的卡片移除，更新的欄位回到匯入前的值。整筆一起復原。
- 「**再匯入另一份來源**」：回到步驟 1。

## 9. 判讀品質的 benchmark

為了知道 AI 判讀可不可靠，專案裡有一組小型 benchmark：`tests/fixtures/bi_ingest_benchmark/`。

- 5 份**虛構**筆記（機器人、Wi-Fi 7、RedCap 競品、UWB 晶片商、AMR 趨勢），每份都標明「虛構範例」，
  不含任何真實客戶資料。
- 每份筆記有一個 `*.expected.json`，寫下「應該」產生的卡片，以及每個欄位應該是：
  - `fact`：有出處，並指定出處應該是原文的哪一句；
  - `inference`：只能是推論；
  - `unknown`：原文沒寫，不應該被宣稱（不能用常識補成事實）；
  - `duplicates`：兩種寫法應該是同一張卡，或被標成名稱相近；
  - `forbidden`：不應產生的東西（例如沒有需求的商機、把代理商當成競爭對手）。
- **請你（領域負責人）審閱這些 expected 檔**：答案是不是你會給的答案？欄位的 `why` 說明了理由。
  有不同意見就改 expected 檔或告訴工程人員。
- 評分項目：找到幾張應有的卡、依據標錯幾個、出處不符或沒有出處幾個、不應產生卻產生幾個、
  重複名稱沒合併幾組，以及總分與逐條的失敗原因。

執行方式（需要在有 AEP 原始碼的電腦上，由會用命令列的人執行）：

```
# 用 host 設定裡的 Knowledge 模型實際跑一次（只試跑，不寫入卡片）
python scripts/bi_ingest_benchmark.py run --config <host 設定 JSON> --dataset <資料集>

# 或：先在 Agent Web 手動試跑（把筆記加入為來源、在步驟 3 試跑），再用執行編號評分
python scripts/bi_ingest_benchmark.py score --workspace <workspace 資料夾> --dataset <資料集> \
    --run 01_robot_tsn_meeting.md=<執行編號> --run 02_wifi7_module_quote.md=<執行編號> ...
```

`run` 會把筆記以 `UNCLASSIFIED` 加入來源（模型的資料核准必須包含 `UNCLASSIFIED`）、每份筆記指定
expected 檔裡的卡片類型做試跑、等待完成、評分，報告寫在 `<workspace>/bi/benchmarks/`。報告會寫明哪些是
自動的、`bi.sqlite` 前後是否相同。手動在 Agent Web 試跑時，頁面預設只讀三種卡片，商機、競爭對手、
生態系、趨勢等類型要用擷取 Skill 調整「卡片類型」，否則那些項目會被算成沒找到。

## 9.5 Dashboard 的「應用領域 × 技術領域」

BI 卡片 → Dashboard 最上面是覆蓋矩陣：欄是 5 個市場的 11 個應用領域（標「重點」的是市場應用圖上的
重點應用），列是 5 個技術領域。每格是卡片數；按一下看這一格的有出處比例、最近更新、最常空著的欄位，
以及卡片清單（點卡片名稱開啟）。矩陣用 vault 的設定，沒有就用預設的市場應用圖。

卡片要有「應用領域（segments）」與「技術領域（tech_areas）」兩個欄位才放得進矩陣；目前內建 schema 還
沒有，畫面會提示你用 Session A 加上這兩個欄位、發布並升級後再補標。對不上矩陣的值會列在表格下方。

## 9.6 全文搜尋（卡片與原文）

BI 卡片 → 卡片 → 「**全文搜尋（卡片與原文）**」：一次找卡片欄位的值與所有來源 Markdown 的原文，命中的字
會標出來；原文會寫是哪份來源、第幾版、第幾行。三個字以上的詞用索引，短詞改逐筆比對。旁邊會寫索引有幾張
卡片、幾段原文、何時更新；「**重建索引**」可整份重建（訂閱來的唯讀資料集沒有這個按鈕）。

## 10. 目前的限制

- **不支援圖片與掃描的 PDF（沒有 OCR）**。有文字層的 PDF、Word、PowerPoint 會自動轉成 Markdown。
- **到目前為止，AI 判讀、Session A、Session B 都只用「腳本模型」（預先寫好的回答）測試過，還沒有用真實
  模型跑過**。真實模型的品質請用第 9 節的 benchmark 實測後再信任；在那之前，每張候選卡都請仔細審核。
- AI 判讀的頁面沒有選卡片類型的欄位；要用擷取 Skill（Session B）調整。
- 名稱比對只忽略空白、標點與大小寫；中英文或簡稱與全名需要你在審核時處理。
- 每一個寫入都需要你在步驟 5 按「確認匯入」；分數再高也不會自動寫入。
