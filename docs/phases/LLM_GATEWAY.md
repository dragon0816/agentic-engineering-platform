## Owner decision (2026-10-16)

The AEP Windows installer must include the LLM gateway: without it AEP's Agent cannot
reach any model. Today every host's `host.json` points the `company` endpoint at
`http://127.0.0.1:4000/v1` (`deploy/windows-preview/gateway-default.json`, provider
`openai_compatible`, credential `litellm_gateway` -> environment variable
`LITELLM_MASTER_KEY`, `data_approval.internal_gateway: true`), but nothing AEP ships
serves that address; on the owner's PC it is a hand-built LiteLLM proxy.

Coordinator finding (2026-10-16): after a reboot the owner's gateway took 9-12 minutes
to serve, because `import litellm` first fetches its model cost map from
raw.githubusercontent.com, which behind the company proxy fails
(`CERTIFICATE_VERIFY_FAILED`) only after a timeout; meanwhile AEP answered "The
configured model could not answer this turn". Required: offline flags by default; in
phase B a model-failure answer that says the gateway is not running / still starting
(probe `/health/liveliness`) with a pointer to Settings > LLM gateway (Web and
Telegram); the Settings card shows "starting..." while the process exists but the port
does not serve yet.

Facts established from the source:

- **Where the token lives today**: `customized_LLM_vscode_plugin\.env` (plus `.env.bak`
  and dated snapshots), keys `CHATRS_TOKEN` (the chatrs Open WebUI JWT, 28 days) and
  `LITELLM_MASTER_KEY` (local gateway password, `sk-chatrs-` + 24 hex, generated by
  `refresh-token.ps1` when empty, never regenerated). Not read, not copied. AEP keeps
  the same mechanism outside the repository: a `NAME=value` token file in the user's
  profile (below).
- **Why no personal API key**: the service has `ENABLE_API_KEY=false` (still 403 when
  checked), so the JWT is renewed by Windows integrated authentication: chatrs ->
  Keycloak answers `WWW-Authenticate: Negotiate`; a domain-joined PC's Kerberos ticket
  completes SPNEGO silently (no password stored, no browser, no MFA). Redirects must be
  followed one hop at a time (.NET drops credentials across hosts). Needs a live
  ticket: off the domain / VPN without a ticket it fails.
- **Why `hosted_vllm/`**: for `openai/` LiteLLM routes gpt-5.4+ requests with tools +
  `reasoning_effort` to the Responses API (no opt-out), chatrs has no `/responses` ->
  405. `hosted_vllm/` speaks the same `/chat/completions`.
- **Required LiteLLM setting**: `use_chat_completions_url_for_anthropic_messages: true`
  (otherwise `/v1/messages` -> `{api_base}/responses` -> 405); `drop_params: true`
  (chatrs' non-standard `usage.latency_checkpoint`).
- **Streaming patch**: LiteLLM's Anthropic streaming adapter indexes
  `chunk.choices[0]` unguarded; chatrs emits a chunk with `choices: []`. The patch
  filters those at the private `_CombinedChunkSplitter` and fails loudly if it moved.
- **Autostart**: a Task Scheduler task `LiteLLM_Gateway` registered with admin rights
  (replacing a Startup-folder `.vbs`); a duplicate guard (port already listening ->
  exit quietly); deliberately no restart loop (a bad token would look like a crash
  loop); log capped at 10 MB.
- **Verified versions**: the live gateway runs LiteLLM **1.94.1** on Python 3.12.7
  (`litellm[proxy]`, fastapi 0.141.1, pydantic 2.13.4, uvicorn 0.52.0, numpy 2.5.1).

## Design

### Component: `src/llm_gateway/` (new top-level package)

Standard library only, except `launcher` and `patch` (which run in the gateway's own
environment, where LiteLLM is). AEP's process never imports LiteLLM.

| Module | Role |
|---|---|
| `config.py` | gateway home and files, `GatewaySettings` (port, upstream, default model, model list, optional external token file, gateway Python), `render_config` (LiteLLM YAML with `os.environ/...` references only), `validate_config_text` (no YAML parser needed: required markers, no `openai/`, no credential-looking value), `init_home` (writes only what is missing; `--force` re-renders the YAML from `gateway.json`) |
| `secrets_file.py` | the token file (`NAME=value`, `.bak` on every write), JWT expiry (unverified decode, expiry only), `TokenInfo` (present/readable/expires/days left, never the value), local key: generated once (`sk-aep-` + 32 hex), never changed; the environment's `LITELLM_MASTER_KEY` (what AEP's credential mapping reads) wins over the file's so both agree |
| `patch.py` | the streaming patch, ported; idempotent; `GatewayPatchError` when the module, the class or `__next__`/`__anext__` moved |
| `launcher.py` | `python -m llm_gateway.launcher --home H [--port N] [--refresh-if-due]`: optional token refresh, settings + config validation, token file into this process only, refuse missing/expired token, exit 0 when the port is already served, offline environment, version warning when not 1.94.1, patch, record pid, `run_server --host 127.0.0.1` |
| `control.py` | `status` (serving / starting / stopped, `ours`), `start` (detached, windowless, log `logs/gateway.log` rotated at 10 MB), `stop` (only the process AEP started; another gateway on the port is reported, never killed), `test` (GET `/v1/models`, then "Reply with exactly: OK" per model; HTTP 401/404/405/429 mapped to plain hints), autostart on/off |
| `token_refresh.py` | the Kerberos refresh: embedded PowerShell (port of `refresh-token.ps1`) prints `AEP-TOKEN:<jwt>` on a pipe; Python checks readable / unexpired / changed before writing; named failures (`no_kerberos_ticket`, `kerberos_rejected`, `no_token_issued`, ...) recorded in `state.json` |
| `state.py` | `state.json`: pid, started_at, port, last_refresh_at / error, last test summary (no values) |
| `cli.py` | `aep-host gateway init / status [--json] / start [--wait] / stop / restart / test [--model] / refresh-token [--force] [--restart] / autostart --on/--off`; prints no token or key value |

Gateway home: `%LOCALAPPDATA%\AgenticEngineeringPlatform\gateway\` (override
`AEP_GATEWAY_HOME`), all in the user's profile, none of it in the repository or bundle:
`gateway.json`, `litellm-config.yaml`, `gateway.env` (token file), `state.json`,
`logs\gateway.log`. An existing token file elsewhere can be used with
`gateway.json` `secrets_file` (for this PC: the live `.env`, see below).

Offline LiteLLM environment set by the launcher (only where the person has not set
it): `LITELLM_LOCAL_MODEL_COST_MAP`, `LITELLM_LOCAL_ANTHROPIC_BETA_HEADERS`,
`LITELLM_LOCAL_BLOG_POSTS`, `LITELLM_LOCAL_POLICY_TEMPLATES` (each replaces a
raw.githubusercontent.com fetch with LiteLLM's bundled copy; tiktoken already uses
LiteLLM's bundled cache), `DISABLE_ADMIN_UI`, `NO_DOCS`. These are set **before**
LiteLLM is imported: the cost-map fetch happens at `import litellm`.

Status semantics for the Settings card (phase B): `serving` = `/health/liveliness`
answers on 127.0.0.1:port; `starting` = the process in `state.json` is alive and the
port does not answer yet; `stopped` = neither. `ours=false` while serving = a gateway
AEP did not start (e.g. the owner's own), shown and tested but never stopped.

### Dependencies (offline in the bundle)

- **Licence finding — `litellm[proxy]` cannot be bundled as is.** The `proxy` extra
  hard-requires `litellm-enterprise==0.1.51`, licence `LicenseRef-Proprietary` (BerriAI
  Enterprise License: production use needs a subscription; "it is forbidden to copy,
  merge, publish, distribute ... the Software"). LiteLLM itself (1.94.1) is MIT (its
  `enterprise/` directory is not in the wheel), `litellm-proxy-extras` is MIT. All 36
  imports of `litellm_enterprise` in LiteLLM 1.94.1 are inside `try/except` (checked by
  AST). So the bundle installs **`litellm==1.94.1` without the `proxy` extra plus the
  extra's other requirements listed explicitly**; `pip check` is clean because the
  extra is not requested. Verified: the proxy starts, lists models, answers
  `/v1/chat/completions` and streams `/v1/messages` with no `litellm_enterprise`
  installed.
- **Lock**: `deploy/windows-preview/gateway/requirements.txt`, the exact versions of
  the owner's working gateway (constraints taken from its environment), 106 packages,
  all permissive (MIT, BSD, Apache-2.0, PSF, ISC, MPL-2.0 for certifi/orjson/tqdm
  data, ZPL-2.1 restrictedpython, Unlicense email-validator). Download:
  `pip download -r requirements.txt --no-deps --only-binary=:all: --platform win_amd64
  --python-version 3.12 --implementation cp`. Size: **135 MB of wheels** (polars-runtime
  50 MB, litellm 20 MB, botocore 16 MB, numpy 12 MB). It cannot be trimmed safely:
  without boto3 (and the cloud SDKs) `run_server` refuses to start ("Missing dependency
  No module named 'boto3'"), see "Measurements".
- **Separate virtual environment (deviation to confirm)**: the owner asked to install
  into the AEP venv. The gateway's verified set conflicts with AEP's own pins (AEP's
  `weekly-mail` extra requires `numpy<2`, the gateway runs numpy 2.5.1; LiteLLM pins its
  own pydantic/httpx/openai ranges and changes them between releases). Proposal: the
  installer creates `<InstallRoot>\gateway-venv` from the same Python, installs the
  gateway lock there plus the AEP wheel `--no-deps` (only `llm_gateway` is used there,
  standard library), and sets `gateway.json` `python` to it. AEP's venv keeps running
  `aep-host gateway ...`. If the owner prefers one venv, the lock must be reconciled
  with AEP's pins first.
- **Long paths**: `litellm_proxy_extras` has deep migration folders; installing into a
  venv under a long folder failed with WinError 206 (scratch folder of ~140
  characters). Longest file under `site-packages` is 129 characters; with the default
  `%LOCALAPPDATA%\AgenticEngineeringPlatform\preview-0.1.0\gateway-venv\Lib\site-packages\`
  a user name up to ~30 characters stays under 260. Phase B: the installer checks the
  path length up front and fails with a clear message (or uses a shorter folder).

### Autostart

Task Scheduler, current user, at logon, `RunLevel Limited`, no elevation, no time
limit, `MultipleInstances IgnoreNew`, no restart on failure (owner's rationale), action
`pythonw.exe -m llm_gateway.launcher --home <home> --refresh-if-due` (renews the token
first when it has 7 days or less, best effort). Task name `AEP LLM Gateway`. If Task
Scheduler refuses a logon task without elevation, fall back to the user's
`HKCU\...\Run` value of the same name. `--off` removes both. Never touches other tasks
(e.g. the owner's `LiteLLM_Gateway`).

### Agent Web (phase B)

Settings card "LLM gateway": state (serving / starting... / stopped, and "not started by
AEP" when `ours=false`), port, address, token expiry and last refresh (no value), last
test per model, buttons Start / Restart / Refresh token / Test, autostart switch.
Routes call `llm_gateway.control` / `token_refresh` (background thread for Test and
Refresh). The Natural-language model card says "uses the built-in gateway at
127.0.0.1:<port>" with a link to the card when its base URL is that address.

Model-failure message (Web and Telegram): when a turn fails on the `company` endpoint
and its base URL is the gateway's, probe `/health/liveliness` (and `state.json`): "The
LLM gateway is not running" / "The LLM gateway is still starting (started N s ago)" /
"The LLM gateway answered 401: the token has probably expired" + "Settings > LLM
gateway", instead of "The configured model could not answer this turn".

### Installer (phase B)

`install.ps1` / `update.ps1` unless `-NoGateway`: create/refresh `gateway-venv` from
`wheels-gateway\` (`--no-index --no-deps -r gateway\requirements.txt`), install the AEP
wheel there `--no-deps`, `aep-host gateway init` (writes `gateway.json`,
`litellm-config.yaml`, generates the local key into the token file when none exists in
the file or the environment, and sets the user environment variable
`LITELLM_MASTER_KEY` when it is not set), set `gateway.json` `python`, merge
`gateway-default.json` into `host.json` only when it has no `models` yet, try
`aep-host gateway refresh-token` (domain sign-in; a failure is reported, not fatal),
`aep-host gateway autostart --on`, `aep-host gateway start`. Update keeps
`gateway.json`, the YAML and the token file. Uninstall: `autostart --off`, `stop`.
Builder: download the lock into `wheels-gateway\`, refuse a bundle missing any wheel,
scan everything added for credentials, keep the path-length check. `verify.yml`: the
bundle smoke installs the gateway offline and runs `aep-host gateway status --json`
(state stopped, config ok, LiteLLM 1.94.1) and `python -m llm_gateway.launcher` with no
token (exit 2, "missing CHATRS_TOKEN"); no real calls (no chatrs / Kerberos in CI).
`pyproject.toml`: an optional `gateway` extra documenting the lock's top-level names
(without `litellm[proxy]`), and an `ignore_missing_imports` mypy override for
`litellm` only if a module ever imports it statically (phase A imports it through
`importlib`, so none is needed).

### This PC (phase B)

Port 4000 is served by the owner's gateway (AEP, Hermes and Claude Code use it). The
AEP gateway must not start a second one or touch it: `start` reports `serving`,
`ours=false`; `stop` refuses. Options for the owner: (a) keep the owner's gateway, set
`gateway.json` `secrets_file` to its `.env` so status shows the real token expiry, and
leave AEP's autostart off; (b) later switch to AEP's gateway: stop the old task, `aep-host
gateway autostart --on`. Default: (a).

## Measurements (2026-10-16, this PC, fake upstream on loopback, ports 4317/4318)

- Pinned set installed offline into a fresh Python 3.12 venv from 106 wheels: `pip
  check` clean, no `litellm_enterprise`.
- `python -m llm_gateway.launcher` with the offline flags: serving after **52-76 s cold**
  (first start after install, machine busy installing another venv in parallel) and
  **9-34 s warm**; no `raw.githubusercontent.com` fetch in the log (without the flags,
  `import litellm` logs `CERTIFICATE_VERIFY_FAILED` for the cost map).
- Through the gateway: `/v1/models` lists the 11 names; `/v1/chat/completions` and
  `aep-host gateway test` answer; Anthropic `/v1/messages` streaming returns
  `text_delta`s for an upstream that sends an empty-`choices` chunk first and mid-stream.
- The same fake stream also worked **without** the patch on 1.94.1, so the fake does not
  reproduce chatrs' failure; the patch is kept because the owner verified it against
  the real service. The real-service check is `aep-host gateway test` plus a streaming
  `/v1/messages` call on a domain PC (owner).
- Trimmed set (without polars, boto3/botocore, azure, msal, soundfile, mcp, numpy,
  pywin32; 88 packages): LiteLLM's `run_server` exits with `ModuleNotFoundError: Missing
  dependency No module named 'boto3'`. The full lock ships.
- `stop` stopped only the gateway it started; the owner's gateway on port 4000 kept
  answering throughout.

## Phase B as built

- `managed` in `gateway.json` (default true). False: `start`, `stop`, `restart`,
  `refresh-token` and `autostart --on` are refused with `not_managed`; status and
  test work; `init` writes no key. `aep-host gateway init` takes `--python`,
  `--port`, `--secrets-file`, `--unmanaged`, `--user-env` (exports the local key to
  the user variable `LITELLM_MASTER_KEY` only when none exists).
- `autostart --off` queries first and removes only what exists (the task, the Run
  value), so a computer without AEP's task sees a query and nothing else.
- `host_runtime/gateway_link.py`: `explain_model_failure` (codes `model_unreachable`,
  `model_timeout`, `model_error`, `model_http_error`, `model_unavailable` on a
  loopback endpoint: not running / still starting (started N s ago) / 401 / 405) and
  `gateway_card`. Agent Web: `GET/POST /api/settings/gateway`, the card before the
  Natural-language model card ("Uses the built-in gateway at 127.0.0.1:4000"),
  polling every 2 s while starting. Telegram: `TelegramIngress.explain_failure`, set
  by `build_telegram`.
- Installer: `-NoGateway`, `-GatewayInstallOnly`; model merge only without
  `models`; long-path pre-check (deepest LiteLLM file 129 characters below
  `site-packages`); `gateway stop` before reinstalling `gateway-venv`; best-effort
  token refresh, autostart, start. `update.ps1` stops AEP's gateway first and passes
  `-NoGateway`; `uninstall.ps1 -Apply` switches autostart off and stops AEP's gateway,
  keeping the gateway home.
- Builder: `--gateway-wheel-dir`, exactly one wheel per locked package (refused
  otherwise), copied to `wheels-gateway/`; the credential scan covers the lock.
  `release_windows.py` downloads the lock with `--no-deps`. CI: downloads the lock,
  installs with `-GatewayInstallOnly`, checks model routing, `gateway status --json`
  (stopped, config ok, managed, LiteLLM = pinned), the patch against the bundled
  LiteLLM, the launcher's exit 2 without a token, and that a reinstall keeps
  `gateway.json`.
- No `gateway` extra in `pyproject.toml`: an extra cannot express "LiteLLM without
  its `proxy` extra plus the proxy's other requirements at exact versions"; the lock
  file is the single source, and `litellm` is never imported statically (no mypy
  override needed).
