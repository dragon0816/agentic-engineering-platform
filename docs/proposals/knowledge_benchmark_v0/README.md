## 狀態與使用規則

- **Benchmark Owner：owner。** 建議的 Domain Reviewer：BD、PM、AE（**尚未指派正式審閱者**）。
- 每題 `review_status: draft-unreviewed`。**未經審閱的 Expected Answer 不是正式 Ground Truth**；以它評分的結果只能當作參考（indicative），不能作為 go / no-go 依據（§5.6）。
- 措辭全部合成：Account（Alpha、Beta、Gamma、Delta、Epsilon、Sigma、Tau）、Ecosystem 供應商（Kappa、Lambda、Mu、Nu、Xi、Omicron、Pi）、CustomerProduct、Opportunity、Competitor A / B 都是虛構的，不含任何真實客戶或供應商資料。技術詞彙（Wi-Fi 7/8、5G-RedCap、5G FWA、CPO、800G、PSU、77 GHz 雷達、6G、NTN）為公開領域用語。
- **類型與關係名稱取自 owner 的 BI 知識庫文件**（內部文件，未放入 repo）：分析鏈 Trend → Technology → Node → Ecosystem → CustomerProduct → Application → TestSolution → Opportunity，連結欄位 `related_tech`、`affects_nodes`、`node`、`technologies`、`applications`、`competing_solutions`、`vendor` 等；細節與頁碼見 [bi_schema_v0](../bi_schema_v0/README.md)。
- 實體寫法 `<EntityType>:<canonical_key>`，關係寫法為三元組 `subject —relationship→ object`（方向與 BI 文件的卡片欄位相同：欄位所在的卡片是 subject）。`TestSolution:*`、`Concept:*` 表示任何該類型的卡（用於「不應存在」的關係）。
- `corpus: synthetic_fixture`：題目可由 mock 背後的合成文件回答。`real_vault_candidate: true` 的題目（Market Trend、Technology & Ecosystem、Application & Test Solution）可由審閱者改寫並對應到真實 vault 的副本；含 Account 的題目維持合成。
- 結構比照 `benchmarks/knowledge_v1/questions/questions.json`（`id`、題目文字、標籤），另加 Relationship Accuracy 所需的 gold triples 與證據要求；正式版定稿後比照 `benchmarks/knowledge_v1/questions.py` 以 sha256 pin。
